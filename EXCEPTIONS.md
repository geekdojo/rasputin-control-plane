# Approved standard exceptions

Every departure this repo makes from a [Geekdojo development principle](https://github.com/geekdojo/geekdojo-brain/blob/main/engineering/development-principles.md), each approved by Bryce on its `PolicyException` issue. The process and this table's format are in [Standard exceptions](https://github.com/geekdojo/geekdojo-brain/blob/main/engineering/standard-exceptions.md). A departure that matches a row here is not a review finding. When a row's revisit fact becomes true, the code is brought into line and the row is removed in the same change.

| ID | Rule | Where | Departure | Constraint | Revisit fact | Approved |
|---|---|---|---|---|---|---|
| EX-1 | ERR-CLOSED | `api/internal/api/door/breach.go`, `Handler.warned`; `api/internal/breachcheck`, `Checker.Listed` | When the sign-in door cannot get an answer from the breached-password range API (DNS, connect, TLS, timeout, a non-200 or malformed answer), a post that sets a password is relayed to Keycloak without the breached-password warning, and one WARN `breach_check=unavailable` with its error class is logged. Nothing is cached, and no later request is affected. | `decision`: Bryce ruled "A plus an HIBP warning" (2026-11-23), a warning the person can dismiss and keep, never a refusal, and approved "Offline it fails open and A's list still applies". `true-now`: the check grants nothing, since relaying without it is what "Keep this password" gives; the gating check is Keycloak's `passwordBlacklist` (`api/internal/identity/flows/realm.go`, `PasswordPolicy`), which runs in-process, works offline and fails closed. | A breached-password source the door can query without leaving the cluster ships in the image, for example a local copy of the range data. | [geekdojo/geekdojo-brain#1146](https://github.com/geekdojo/geekdojo-brain/issues/1146) |
