# Approved exceptions — rasputin-control-plane

Each row is a departure from the [Geekdojo development principles](https://github.com/geekdojo/geekdojo-brain/blob/main/engineering/development-principles.md) that Bryce has approved, in the register form [Standard exceptions](https://github.com/geekdojo/geekdojo-brain/blob/main/engineering/standard-exceptions.md) sets out. A departure that matches a row here is not a review finding. When a row's revisit fact becomes true, the code is brought into line and the row is removed in the same change. IDs are never reused. Authentication exceptions are not listed here: they stay in the authentication register, [`.github/auth-register.tsv`](.github/auth-register.tsv), which CI checks.

| EX-1 | SEC-ENCRYPT | `api/internal/api/obs_proxy.go`, `Server.handleObservabilityProxy`; `api/internal/obs/supervisor.go`, `grafanaIniTmpl` (`[server] protocol = socket`) | The api relays the console's `/observability/` requests to Grafana over plain HTTP on Grafana's private Unix socket: mode 0600, in a 0700 directory that only Grafana's uid may enter (`api/internal/obs/grafana_socket.go`). The approval covers the leg once the identity design's item Identity roles 4 has narrowed what it carries about a person to the opaque account id in `X-Webauth-User` and a role header that maps every console role to Viewer, with no name or email. Beyond that the leg carries the dashboard requests and responses and Grafana's own session cookie, never Rasputin's cookies. Linux control planes only: the non-Linux developer fallback, Grafana on a TCP port, is not covered. | `true-now`. Grafana believes `X-Webauth-User` from any caller that can connect, and its only allowlist matches a source IP, which a Unix socket does not have, so the socket's permissions are what limit the callers (geekdojo/geekdojo-brain#453). At the pinned Grafana, 11.5.1, the socket protocol is served as plain HTTP; TLS runs only on a TCP listener, and it takes a server certificate with no option to require a client certificate ([`pkg/setting/setting.go:1841-1860`](https://github.com/grafana/grafana/blob/c6c701cf5be984b088b9d51690b474ab63ca86ff/pkg/setting/setting.go#L1841-L1860), [`pkg/api/http_server.go:451-493`](https://github.com/grafana/grafana/blob/c6c701cf5be984b088b9d51690b474ab63ca86ff/pkg/api/http_server.go#L451-L493) and [`:922-926`](https://github.com/grafana/grafana/blob/c6c701cf5be984b088b9d51690b474ab63ca86ff/pkg/api/http_server.go#L922-L926), at v11.5.1). An encrypted listener could therefore not tell the api from any other local caller. | Grafana can serve TLS on its socket, or the api can reach it over mutual TLS. Tracked by [geekdojo/geekdojo-brain#944](https://github.com/geekdojo/geekdojo-brain/issues/944). | Bryce, 2026-11-02, [geekdojo/geekdojo-brain#943](https://github.com/geekdojo/geekdojo-brain/issues/943) (ruling D24 of the identity design, under the IAM and audit epic, geekdojo/geekdojo-brain#317): "record the exception but log an issue to track this under E11 (#278)." |
